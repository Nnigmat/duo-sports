# Сборка тренировки агентом

## Зачем

Сейчас тренер создаёт тренировку в трёх местах. Состав пишет во внешнем агенте по скопированному
`exercises.yaml` и вставляет YAML в импорт. Форма редактора не даёт добавить упражнение, которого
нет в библиотеке. Новые разминки и заминки заводятся отдельно, на странице разминок. Нужен один
флоу внутри приложения: описал словами и выбрал готовое, агент собрал, тренер проверил и поправил
в форме, одно «Сохранить» создало всё.

## Цели

- Страница «Новая тренировка» для тренера и админа: разминка, основная часть, заминка. Разминку
  и заминку выбирают из библиотеки или описывают текстом; основную часть описывают текстом и
  одновременно добавляют упражнения из библиотеки.
- Агент на Haiku 5.5 (`claude-haiku-5-5`) собирает тренировку из библиотеки упражнений, списка
  разминок и заминок, правил админа, формата тренировки и ввода тренера.
- Результат открывается в форме редактора. Форма умеет новые упражнения и новую разминку или
  заминку с пометкой «новое»; поля нового упражнения заполнены агентом, тренер их правит.
- Над формой заметки агента: «В библиотеке есть похожее — Отжимания на брусьях» с кнопкой
  «Заменить».
- «Сохранить» одним запросом создаёт новые упражнения, новую разминку или заминку, тренировку и
  ставит её на выбранный день. Отменяется как импорт.
- Страница админа с правилами для агента: один текст.

## Не цели

- Генерация видео и SVG-поз чибика для новых упражнений. Отдельный проект позже: у видео и поз
  общая инфраструктура (хранение, предпросмотр, перегенерация).
- Доступ спортсмена. У спортсмена кнопка «Создать тренировку» ведёт в импорт, как сейчас.
- Чат с агентом и правка готовой тренировки агентом. Итерация — только «Пересобрать».
- Планы на много недель через агента: для них остаётся импорт YAML.
- Новые упражнения в редакторе уже сохранённой тренировки (`WorkoutEditPage`). Он сохраняет через
  `updateWorkout`, который упражнений не создаёт; расширять его — отдельная задача.

## Анти-цели

- Агент тихо плодит дубли: создаёт новое упражнение, когда в библиотеке есть то же самое.
- Что-то попадает в базу без проверки тренером.
- Ключ API в репозитории, в браузере или в логах.
- Агент выбрасывает упражнения, которые тренер явно выбрал из библиотеки, и это не видно.

## Ограничения

- Стек проекта: Express, better-sqlite3 без ORM, React, CSS на `tokens.css`, Radix только для
  поведения. Интерфейс по правилам CLAUDE.md (русский, без «!», кнопки от 44 px, tabular-nums).
- Создавать упражнения и разминки могут только trainer и admin (`canAddExercises`); это не меняется.
- Разминки и заминки общие для всех пользователей (GLOSSARY.md).
- Ключ: `ANTHROPIC_API_KEY` только на сервере. На прод — через GitHub Secret, как `SENTRY_DSN`.
- В CI ключа нет: тесты не ходят в сеть.

## Подходы

Ответ агента и путь до формы:

1. **YAML в формате импорта.** Разбор уже есть, но маленькая модель ошибается в отступах и
   кавычках, нужны повторы.
2. **JSON строго по схеме (structured outputs), схема повторяет формат импорта — выбран.** Форма
   ответа гарантирована, а содержимое проходит через существующий `parseImport`: сопоставление
   названий и алиасов с библиотекой, поиск новых упражнений, проверка `routine`. В схему добавлены
   только заметки агента и поля новых упражнений.
3. **Агент с инструментами** (поиск упражнения, чтение разминки) в цикле. Отброшен: библиотека
   целиком помещается в один запрос, цикл медленнее, дороже и хуже тестируется.

Проверка результата: в форме редактора, научив её новым упражнениям и разминкам (выбрано), а не в
шагах импорта — там правка возвращает в YAML-текст, то есть почти к нынешней боли.

Доступ: только тренер и админ (выбрано). Отброшены «всем, спортсмену с урезанными правами» (две
ветки поведения) и «всем с полными правами» (меняет правило библиотеки, риск дублей).

Позы чибика: агент позы не выбирает. Поза в данных есть только в `Exercise.pose` структуры
тренировки и в реальных данных нигде не задаётся; персонаж упражнения — это демо-ролики
`LibraryEntry.demo`. Позы и видео — в проекте про медиа новых упражнений.

## Как устроено

### Вход

- «Создать тренировку» в плане ученика (`AthletePlanPage`) и в своём плане (`PlanPage`) у тренера
  и админа ведёт на новую страницу с датой: `/trainer/athletes/:id/new?date=…` и `/plan/new?date=…`
  (точные пути — на усмотрение исполнителя). У спортсмена — `/import?date=…`, как сейчас.

### Страница ввода

```
Новая тренировка · вт 18 ноя
Название [                         ]   (необязательно — придумает агент)

Разминка
 ○ Шея и плечи   ○ Суставная   ● Описать свою   ○ Без разминки
 [ 5 мин суставная, акцент на плечи        ]

Основная часть
 [ жим лёжа 4×8 60 кг, потом суперсет      ]
 [ бицепс + трицепс, 3 круга               ]
 + Из библиотеки:  [Жим лёжа ×] [Подтягивания ×]

Заминка
 ● Растяжка спины   ○ Описать свою   ○ Без заминки

            [ Собрать тренировку ]
```

- Выбор из библиотеки в основной части — поиск по библиотеке (как в `WorkoutEditView`), выбранные
  чипами с кнопкой удаления.
- Пока идёт сборка, кнопка занята. Ввод сохраняется в черновик браузера (см. «Черновик в браузере»). Ошибка — сообщение на экране, ввод не теряется.
- Без ключа на сервере эндпоинт отвечает 503, страница пишет «Сборка недоступна» и даёт ссылку на
  импорт.

### Запрос к агенту

`POST /api/ai/workout-draft`, только trainer и admin (для ученика — проверка `canAccessAthlete`).
Тело: дата, название, разминка `{ routine: slug } | { text } | null`, основная часть
`{ text, exercises: slug[] }`, заминка как разминка, необязательно `errors` — ошибки разбора
прошлой попытки. Ответ: JSON по схеме и счётчики токенов.

Сервер собирает запрос в порядке от самого стабильного к самому изменчивому, потому что кеш
совпадает только по началу:

1. Инструкции агенту и схема ответа — из кода.
2. Описание формата тренировки — из кода (на основе `web/src/features/import/format.ts`).
3. Правила админа. ← точка кеша
4. Разминки и заминки: slug, вид, название, упражнения.
5. Библиотека упражнений: только id, name, aliases, kind, muscles, equipment. Без `demo` и прочих
   полей, которые меняются сами. ← точка кеша
6. Ввод тренера — не кешируется.

Сериализация детерминированная: сортировка по id, без дат и случайного порядка, иначе кеш не
сработает. TTL кеша — стандартные 5 минут. Цены Haiku 5.5 (за миллион токенов): ввод $0.10, вывод
$0.50, запись в кеш $0.125, чтение $0.01. Сборка — около 12 тыс. токенов ввода и 2–3 тыс. вывода, то
есть примерно $0.003; кеш экономит доли цента и в основном ускоряет «Пересобрать». Поэтому TTL 1 час
(запись дороже) не нужен. Исполнитель сверяет с документацией Anthropic:
минимальную кешируемую длину для Haiku 5.5, лимит в 4 точки кеша,
поддерживаемые ключевые слова JSON Schema для structured outputs у `claude-haiku-5-5`. Если
structured outputs для модели нет — принудительный вызов инструмента с той же схемой.

Клиент Anthropic — пакет `@anthropic-ai/sdk` (новая зависимость: типизированные structured
outputs, повторы при сбоях API). Он спрятан за интерфейсом, в тестах — подделка.

Лимиты: длина каждого текстового поля (например, до 2000 символов), таймаут запроса. В лог (pino)
— пользователь и токены: input, cache_creation, cache_read, output. Текст ввода и ответ в лог не
пишутся.

### Схема ответа

Подмножество формата импорта для одной тренировки плюс два поля:

- `title`, `notes`;
- `warmup` / `cooldown`: `{ routine: slug }`, `{ new_routine: { id, title, exercises: [...] } }`
  или `null`; упражнения набора — как в `routines:` импорта (`exercise_id` или `name`, `time`,
  `per_side`, `sides`);
- `blocks`: блоки основной части как в импорте (`sets`, `circuit`, `superset`, `timed`) с
  упражнениями `exercise_id | name`, `do | sets/reps/weight`, `time`, `rest`, `per_side`, `notes`;
- `new_exercises`: `{ id (slug), name, muscles, measure, equipment, notes, aliases }` — у нового
  упражнения всегда явный slug, чтобы на него могла сослаться новая разминка;
- `advice`: заметки `{ text, exercise?: имя в тренировке, suggest?: slug из библиотеки }`.

### От ответа к форме

Чистые функции в браузере (с тестами):

1. Ответ превращается в документ импорта (`version: 1`, `exercises`, `routines`, одна тренировка
   с `date` и блоками warmup/cooldown по `routine`) и проходит через `yaml.stringify` — чтобы
   номера строк в ошибках `parseImport` были осмысленными.
2. `parseImport` с контекстом библиотеки. Ошибки разбора — один автоматический повтор: клиент
   снова зовёт эндпоинт с `errors`. Не вышло и со второго раза — ошибки на экране и «Пересобрать».
3. Проверка, что все выбранные тренером упражнения есть в тренировке; пропавшие — отдельной
   заметкой над формой.
4. Результат — черновик редактора: название, блоки, новые упражнения, разминка и заминка (ссылка
   или новая).

### Проверка в форме

Форма — `WorkoutEditView`, расширенная:

- **Новое упражнение** в блоке с пометкой «новое» (не только цветом — текстом). По нажатию — панель
  с полями: название, мышцы, тип (повторы, вес, время), инвентарь, техника. Заполнены агентом.
  Кнопка «Убрать» и, если агент нашёл похожее, «Использовать похожее».
- **Добавить новое упражнение руками**: в поиске по библиотеке, когда ничего не нашлось, —
  «Создать „…“». Это закрывает вторую боль и без агента.
- **Новая разминка или заминка** показывается блоком по таймеру с пометкой «новая разминка»:
  название, упражнения, секунды, порядок, удаление. Выбранная из библиотеки — строкой, как сейчас.
- **Заметки агента** над формой; у заметки с `suggest` — «Заменить», которая меняет упражнение на
  библиотечное и убирает новое, если оно больше нигде не используется.
- «Пересобрать» — назад к вводу, введённое сохранено, правки формы теряются (предупредить).
- «Сохранить».

### Сохранение

Через существующий импорт, без нового пути записи: черновик → `ImportCommit` (новые упражнения в
`exercises` с явным `id`, новая разминка в `routines`, одна тренировка с `structure` и ссылками
`warmupRoutine`/`cooldownRoutine`, одна запись в `entries` на дату, `replaceDates: []`) →
`POST /api/imports` или `/api/trainer/athletes/:id/imports`. `applyImport` в одной транзакции
вставляет упражнения, потом разминки (`createRoutine` уже видит новые упражнения по slug), потом
тренировку и запись плана. Отмена — как у импорта.

Конфликты, которые надо обработать: название новой разминки уже занято (`createRoutine` отвечает
`duplicate`) — подсказать на форме до отправки; упражнение новой разминки не по времени — разминка
принимает только упражнения на время, форма это проверяет; slug нового упражнения совпал с
библиотечным — `applyImport` такое упражнение молча пропустит, и тренировка сошлётся на чужое,
поэтому перед отправкой slug переименовывается (`-2`, `-3`, как `slugOf` на сервере).

После сохранения — переход в план на этот день.

### Черновик в браузере

Ввод и собранная тренировка не должны теряться при случайной перезагрузке, закрытии вкладки или
вебвью Telegram. Повторная сборка стоит денег и времени, поэтому сохраняется и ответ агента.

- localStorage, по образцу `web/src/features/workout/draftStorage.ts`: каждое чтение и запись в
  try/catch; хранилище недоступно — страница просто работает без восстановления.
- Ключ — пользователь, ученик (или «свой план») и дата: черновики разных дней и учеников не
  смешиваются.
- Что хранится: шаг (ввод или проверка), весь ввод, черновик формы с правками тренера, заметки
  агента. Пишется при каждом изменении (с небольшой задержкой, чтобы не писать на каждую букву).
- Версия формата и срок годности (например, 7 дней). Черновик чужой версии или просроченный
  удаляется при чтении. Разбор сохранённого — чистая функция с тестами.
- При открытии страницы с черновиком: сразу показываем его на том шаге, где остановились, и строку
  «Восстановлен черновик от 17 ноя, 21:40» с кнопкой «Начать заново».
- Черновик удаляется после успешного «Сохранить» и по «Начать заново».
- «Пересобрать» ввод не трогает; правки формы теряются, о чём предупреждаем.

### Правила админа

- Таблица на одну строку: текст, `updated_at`, `updated_by`. Чистый SQL, миграция в `db.ts`.
- `GET /api/admin/ai-rules` и `PUT` — только admin. Нужен серверный и клиентский `RequireAdmin`
  (сейчас есть только `RequireTrainer`).
- Страница: textarea, «Сохранить», строка «Изменено 17 ноя, 21:40 · Никита».
- Начальный текст — пример от пользователя: в разминке и заминке сначала упражнения стоя, потом
  сидя, потом лёжа, чтобы не вставать и не ложиться несколько раз.

### Деплой

`ANTHROPIC_API_KEY` в GitHub Secrets → `env` и строка ssh в `deploy.yml` → предупреждение в цикле
`deploy.sh` → `pm2 restart --update-env`. Локально — переменная окружения, в `.env` не коммитится.

### Тесты

- vitest: сборка запроса (порядок частей, детерминированная сериализация, точки кеша), ответ →
  документ импорта, чтение и запись черновика (версия, срок, битые данные), проверка выбранных упражнений, функции черновика (новое упражнение, замена по
  заметке, новая разминка), черновик → `ImportCommit`.
- Сервер: эндпоинт сборки с подделкой клиента (права, 503 без ключа, лимиты), правила админа (права).
- Storybook-истории новых экранов: ввод, сборка идёт, ошибка, форма с новыми упражнениями и
  заметками, страница правил.

- Текст инструкций агенту (на основе формата импорта и правил) и точная JSON-схема в пределах
  поддерживаемого подмножества.
- Раскладка формы и панели нового упражнения в духе существующего `WorkoutEditView`.
- Как дробить работу на PR: например, правила админа → эндпоинт сборки → страница ввода → форма с
