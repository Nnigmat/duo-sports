# Формат тренировки v2: сборка агентом без отказов

## Зачем

Сборка тренировки агентом (`web/src/features/builder/`) отбрасывает тренировку целиком из-за одной
записи, которую тренер написал естественно. Замер в ноябре 2026 на реальном запросе тренера
(фикстура ниже): с размышлением собралась 1 сборка из 4, причём в двух неудачных агент верно собрал
всё, кроме одного поля; без размышления — 0 из 4. Причины:

- формат допускает несколько способов записать одно и то же (`do` или `sets`/`reps`/`weight`,
  отдых у блока или у упражнения, `per_side` или `sides`, время строкой в четырёх видах), и агент
  выбирает тот, где проще ошибиться;
- формат не умеет того, что тренер пишет: время на максимум, разный отдых в одном блоке,
  не-упражнение (тест), повторы в разминке;
- заметки агента (`notes` тренировки и упражнения) разбор молча выбрасывает: им негде храниться;
- одна ошибка разбора после повтора — и тренер не получает ничего («Агент дважды собрал тренировку
  с ошибками»).

Решение: вторая версия формата с одним способом записи на каждую вещь, новые возможности в модели
и на экране тренировки, черновик с пометками вместо отказа.

## Цели

- `version: 2` формата импорта: один способ записи на каждую вещь. Её пишут агент и YAML-редактор
  тренировки, её описывает страница «Формат импорта».
- `version: 1` разбирается ровно как сейчас; существующие тесты разбора v1 не меняются.
- JSON-ответ агента повторяет YAML v2 одной тренировки плюс `new_exercises` и `advice`.
- Модель и экран тренировки: заметка упражнения, заметка тренировки, отдых у каждого упражнения
  в блоке подходами, отдых после круга, время на максимум (секундомер вверх), шаг-заметка
  с ответом спортсмена, стороны у упражнений основной части.
- В разминке и заминке — любое упражнение библиотеки; время задаёт позиция набора.
- Сборка агентом не отказывает: после одного повтора тренер получает черновик, где неразобранное
  помечено и не даёт сохранить, пока не поправлено.
- Фикстура собирается хотя бы в 3 сборках из 4 без молча выкинутых упражнений (замер делает
  пользователь вручную, см. «Замер»).

## Не цели

- Повторы в разминке и заминке. Разминка остаётся только на время; повторы агент переводит в секунды
  и сообщает об этом в advice.
- Перевод v1 в v2 и правка старых файлов. v1 просто продолжает читаться.
- Мягкий разбор на странице импорта: там файл, и строгость с номерами строк уместна.
- Отдых между блоками: как сейчас, следующий блок начинается сразу.
- Единицы `lb` в v2.
- Автоматический прогон фикстуры против настоящего API в рамках задачи.

## Анти-цели

- Формат превращается в «любой текст»: поле принимает слова и угадывает смысл.
- Значение по умолчанию попадает в план, а тренер не заметил, что оно не от агента.
- Упражнение запроса пропадает из черновика и ни в черновике, ни в advice о нём нет ни слова.
- Старый YAML на странице импорта или в редакторе перестаёт разбираться или разбирается иначе.
- Схема агента перестаёт проходить компиляцию API («Schema is too complex»).

## Ограничения

- `CLAUDE.md` и `CODING_STANDARDS.md`: без ORM, миграции в `migrate()` в `server/db.ts`
  идемпотентно; CSS на `tokens.css`; Radix только для поведения; тексты по-русски без «!»; кнопки
  от 44 px; состояние не только цветом.
- Логика разбора и сценария — чистые функции с тестами vitest; каждая запись из замера — отдельный
  тест.
- Схема агента в strict-режиме structured outputs: не больше 24 необязательных полей и 16 union на
  запрос, у одного объекта не больше 3 необязательных, `minItems` > 1 нельзя. После правки схемы —
  `npm run smoke:ai` (один настоящий запрос; запускает пользователь или исполнитель с его согласия).
- Новое в формате отражается в `server/aiInstructions.ts` и на странице «Формат импорта»
  (`web/src/features/import/format.ts`).
- Номер версии читает только браузер: сервер YAML не разбирает, он проверяет `ImportCommit`
  (`server/imports.ts`, `checkStructure`).

## Подходы

Как устроить разбор двух версий:

1. **v1 → v2, дальше один разбор v2.** Отброшен: v2 уже v1 (нет `name`, `lb`, встроенных
   разминок), а отдых в круге означает разное (в v1 после каждого упражнения, в v2 после круга).
   Точный перевод невозможен, «как прежде» для v1 нарушится.
2. **Один `parseImport`, ветвление по версии в местах, где версии различаются — выбран.** Общими
   остаются поиск в библиотеке, наборы, даты и план, предпросмотр, номера строк. По версии
   различаются чтение упражнения блока (нагрузка, отдых, стороны, заметка), типы блоков, позиции
   набора и поля тренировки.
3. **Отдельный `parseV2`.** Отброшен: 700 строк общего кода в двух копиях.

Решения по содержанию, принятые в разговоре (вопрос → выбор):

- Лишние способы записи → v2 с одним способом; v1 читается как раньше (а не «расширять v1» и не
  «ломать v1»).
- Время на максимум → `time_sec: max`, секундомер вверх (а не «агент ставит число»).
- Отдых → у упражнения в `sets`, после круга в `circuit`; `superset` в v2 убран как дубль `circuit`.
- Стороны → только `sides` из двух подписей, без `per_side`; в инструкции агенту примеры.
- Повторы в разминке → нельзя; агент переводит в секунды и пишет об этом в advice.
- Тип упражнения в разминке → любое упражнение библиотеки; проверка «только time» снимается.
- Заметки и не-упражнения → заметка упражнения, заметка тренировки, блок `note` как шаг с ответом;
  напоминания для тренера — в advice.
- Сборка с ошибками → после повтора черновик с пометками; «Сохранить» недоступна до правки.
- «Дополнит общую разминку» → «Общая разминка» — название набора библиотеки; агент копирует его по
  названию, без выбора основы на странице.

## Как устроено

### Формат v2

```yaml
version: 2
exercises:                      # новые упражнения, как в v1
  - { id: band-pullup, name: Подтягивания с резинкой, measure: weight, muscles: [спина], equipment: [Турник, Резинка] }
routines:                       # новые наборы
  - id: warmup-wrists
    title: Разминка с запястьями
    note: Повторяйте за персонажем
    exercises:
      - { exercise_id: wrist-mobilization, time_sec: 30 }
      - { exercise_id: open-book, time_sec: 15, sides: [влево, вправо] }
workouts:
  - title: Перепроверка старта
    date: 2026-11-20
    notes: Рабочих подходов отжиманий сегодня нет
    blocks:
      - { type: warmup, routine: warmup-wrists }
      - type: sets
        exercises:
          - { exercise_id: pushup-handles, sets: 1, reps: max, rest_sec: 180 }
          - { exercise_id: dead-hang, sets: 1, time_sec: max, rest_sec: 180 }
          - { exercise_id: pullup, sets: 1, reps: max, rest_sec: 180 }
          - { exercise_id: hanging-knee-raise, sets: 1, reps: 10 }
      - type: note
        title: Тест большого пальца
        text: Большой палец в кулак, кисть плавно наклонить к мизинцу. Есть ли резкая боль у основания пальца и насколько сильная.
      - type: sets
        exercises:
          - { exercise_id: band-pullup, sets: 3, reps: 4, weight_kg: 35, rest_sec: 180, notes: Оба колена в петле. Полная амплитуда. }
      - type: circuit
        rounds: 2
        rest_sec: 90
        exercises:
          - { exercise_id: db-curl-seated, reps: 10-12, weight_kg: 8, notes: Локоть упирается в бедро }
          - { exercise_id: lunge, reps: 10, sides: [левая нога, правая нога] }
      - { type: cooldown, routine: cooldown-common }
plan: …                         # как в v1
```

Поля v2:

- Верх: `version: 2`, `exercises`, `routines`, `workouts`, `plan`. Поля `units` нет (вес в кг).
- `exercises[]` (новые упражнения) и `plan` — как в v1.
- `routines[]`: `id`, `title`, `note` (вместо пары `text`/`note`), `exercises[]`:
  `exercise_id`, `time_sec` (целое > 0), `sides` (ровно две подписи) — необязательно.
- `workouts[]`: `id`, `title`, `date`, `notes`, `blocks`.
- Блоки (`type`):
  - `warmup` / `cooldown` — только `routine: <id>` (набор из `routines` файла или библиотеки).
    Встроенных упражнений и `time`/`text` в v2 нет.
  - `sets` — `title`, `exercises`. Подходы каждого упражнения подряд, потом следующее.
  - `circuit` — `title`, `rounds` (по умолчанию 1), `rest_sec` (после круга, по умолчанию 60),
    `exercises`. Между упражнениями круга отдыха нет.
  - `timed` — `title`, `text`, `exercises` с `exercise_id`, `time_sec`, `sides`: упражнения на время
    в основной части, идут сами, как сейчас.
  - `note` — `title`, `text`: шаг-заметка (см. ниже).
- Упражнение в `sets` и `circuit`:
  - `exercise_id` — единственный способ сослаться на упражнение: id библиотеки или `exercises` файла.
    Поиска по `name` нет.
  - `sets` — только в `sets`, целое ≥ 1, по умолчанию 1; в `circuit` — ошибка (подходы задаёт
    `rounds`).
  - Ровно одно из: `reps` (`8`, `"8-12"`, `max`) или `time_sec` (целое > 0 или `max`).
  - `weight_kg` — число ≥ 0, только вместе с `reps`.
  - `rest_sec` — только в `sets`: отдых после каждого подхода этого упражнения, по умолчанию 90;
    в `circuit` у упражнения — ошибка.
  - `sides` — ровно две подписи: нагрузка на каждую сторону; на экране «10 на сторону», шаг
    не делится.
  - `notes` — подсказка к упражнению в этой тренировке.
- Чего в v2 нет: `do`, список подходов (`sets: [...]`), `name` у упражнения блока, `per_side`,
  `superset`, `distance`, `rest`/`time`/`weight` (их заменили поля с единицей в имени). Пирамида —
  несколько строк одного упражнения (редактор так и пишет). Новые упражнения (`exercises`, включая
  `video`) — как в v1.
- Незнакомое поле в v2 — ошибка с подсказкой, какое поле v2 имелось в виду (`do` → «в v2 —
  sets, reps и weight_kg»; `rest` → «rest_sec»; `per_side` → «sides: [влево, вправо]»). Так автор,
  перепутавший версии, сразу видит причину.
- `video_rounds` и `title` у блока — как сейчас в YAML редактора.

Ошибки разбора v2 получают путь до поля (`ParseIssue.path`, например
`['workouts', 0, 'blocks', 2, 'exercises', 1, 'time_sec']`) в дополнение к номеру строки.
Неизвестный `exercise_id` в подсказке называет до трёх ближайших id библиотеки и файла.

### Модель тренировки (`shared/types.ts`, JSON в `workouts.structure`)

Миграция структуры не нужна: новые поля необязательные, старые тренировки идут как раньше.

- `Exercise.note?: string` — заметка к упражнению в этой тренировке.
- `Exercise.sides` — разрешены и в `sets`/`circuit` (сейчас только в таймерном блоке). В таймерном
  блоке, как сейчас, два шага; в `sets`/`circuit` шаг один, на экране «на сторону».
- `SetsExercise.restSec?: number` — отдых после каждого подхода этого упражнения; нет — берётся
  `SetsBlock.restSec`.
- `CircuitBlock.restAfter?: 'round'` — отдых `restSec` только после последнего упражнения круга;
  нет — как сейчас, после каждого упражнения. Новые круги из v2 пишутся с `'round'`.
- Время на максимум: `kind: 'time'`, `target: { min: 0, max: 0 }` — так же, как «макс.» у повторов.
- Новый блок `NoteBlock { id, mode: 'note', title, text }` без упражнений. Как его провести через
  шаги (`Step`), не ломая остальной код, — решение исполнителя; TypeScript покажет все места
  переключения по `mode` (около 20 файлов: экран, сводка, разбор, редактор, сервер).
- Тренировка: колонка `workouts.notes TEXT` (`ALTER TABLE … ADD COLUMN`), `CommitWorkout.notes?`,
  правка в редакторе, показ на экране старта.
- `checkStructure` на сервере принимает всё перечисленное: `note` у упражнения (предел длины как
  у заметок), `sides` вне таймерного блока, `restSec` у упражнения подходов, `restAfter`, блок
  `note` (`title`, `text`, без `exercises`).

### Экран тренировки

- **Отдых** (`buildSteps`): в `sets` после подхода — `exercise.restSec ?? block.restSec`; в
  `circuit` с `restAfter: 'round'` — только после последнего упражнения круга. После последнего шага
  блока отдыха нет, как сейчас (кроме отдыха перед заминкой). Сводка (`summary.ts`) пишет отдых
  по-новому: «Отдых после круга 90 с», а при разном отдыхе в блоке — у упражнений.
- **Время на максимум**: шаг показывает «макс.» вместо времени. «Старт» запускает секундомер вверх
  (без обратного отсчёта и без сигнала конца), «Стоп» открывает окно результата с полем «Время»,
  куда подставлено прошедшее время; его можно поправить. После перезагрузки — снова «Старт», как у
  обратного отсчёта (`afterReload`). Только в `sets` и `circuit`; в таймерных блоках `max` запрещён
  разбором.
- **Заметка упражнения** — на экране подхода под названием, мелким текстом; длинная обрезается
  и раскрывается.
- **Шаг-заметка** (`note`): на своём месте в порядке тренировки, заголовок, текст, необязательное
  поле «Ответ» и «Готово». Ответ уходит в итог тренировки (`SessionResult.answers`, колонка
  `sessions_done.answers`), а не в комментарии: комментарии привязаны к slug упражнения библиотеки,
  а у заметки его нет. Тренер видит ответы в разборе (`server/sessionReview.ts`) разделом «Ответы»:
  заголовок заметки и текст. В подходы итога (`steps`) шаг-заметка не попадает, чтобы не путать
  статистику, прогресс и достижения.
- **Заметка тренировки** — на экране старта над составом.

### Разминка и заминка

- Позиция набора — упражнение библиотеки любого типа и время на одну сторону. Проверка «только time»
  снимается в разборе (v1 и v2: в v1 это расширение, раньше такой файл давал ошибку), в форме набора
  (`RoutineForm`), в форме черновика (`NewRoutineCard`) и на сервере (`createRoutine`, ошибка
  `not_time` и текст `ROUTINE_NOT_TIME`).
- «Похожее» для позиции набора ищется по всей библиотеке, а не только среди упражнений на время.
- Таблица `routine_items` не меняется.

### YAML-редактор тренировки

`workoutToYaml` пишет v2: `exercise_id` по библиотеке (по названию и алиасам, как ищет разбор),
`time_sec`, `weight_kg`, `rest_sec` у упражнения подходов, `rest_sec` у круга с `restAfter`, `sides`,
`notes`, блоки `note`, `notes` тренировки. Если упражнение структуры в библиотеке не нашлось,
в `exercise_id` пишется его название — разбор ответит «Неизвестный exercise_id», как сейчас отвечает
«Упражнения нет в библиотеке».

Старый круг (без `restAfter`, отдых после каждого упражнения) в v2 не выразить. Редактор пишет его
как обычный круг v2 и над текстом показывает предупреждение: «Отдых в круге „…“ после сохранения
будет после круга, а не после каждого упражнения». Без сохранения ничего не меняется. `workoutFromYaml`
принимает обе версии. (Решение автора спека — см. список в конце.)

### Форма редактора (`WorkoutEditView`, она же форма черновика сборки)

Всё, что умеет v2, должно правиться и в форме, иначе пометку в черновике не снять:

- заметка тренировки — поле над блоками;
- у упражнения — заметка; в `sets` — свой отдых (степпер «Отдых», как у блока сейчас; блоковый отдых
  остаётся значением по умолчанию для новых упражнений); переключатель «на максимум» у упражнений
  на время и на повторы;
- стороны у упражнения основной части — показ «на сторону» и снятие; подписи правятся в YAML;
- у круга — «Отдых после круга»;
- блок-заметка: добавить, править заголовок и текст, убрать, переставить.

### Схема и инструкции агента

Схема (`shared/aiDraft.ts`) — JSON-вид YAML v2 одной тренировки:

- Упражнение блока, все поля обязательные, пустое значение — `""`, `0`, `false`, `[]`:
  `exercise_id`, `sets` (integer), `reps` (string: `"8"`, `"8-12"`, `"max"`), `time_sec`
  (`anyOf: [integer, enum ["max"]]` — один union), `weight_kg` (number), `rest_sec` (integer),
  `sides` (array of string), `notes`. Убраны `name`, `do`, `weight`, `time`, `rest`, `per_side`.
- Блок, все поля обязательные: `type` (enum `sets`, `circuit`, `timed`, `note`), `title`, `rounds`,
  `rest_sec`, `text`, `exercises` (без `minItems`: у `note` список пуст, разбор проверяет остальные).
- Позиция набора: `exercise_id`, `time_sec` (integer), `sides` — все обязательные, `[]` — без сторон.
- Тренировка: `notes` становится обязательным (`""` — нет заметки).
- `compactAgentWorkout` чистит пустые значения у новых полей; `isAgentWorkout` проверяет новую форму;
  тест счёта лимитов в `aiDraft.test.ts` обновляется.
- `agentToImportYaml` пишет `version: 2`; ответ почти не преобразуется.

Инструкции (`server/aiInstructions.ts`, `AGENT_INSTRUCTIONS` и `AGENT_FORMAT`) переписываются под v2:

- один способ записи каждого поля, с примерами;
- `sides` — ровно две подписи, примеры: наклоны `[влево, вправо]`, выпады
  `[левая нога, правая нога]`, вращения `[вперёд, назад]`; без сторон — `[]`;
- отдых: в `sets` у каждого упражнения, в `circuit` после круга; цепочку «упражнение → отдых →
  упражнение» ставить одним блоком `sets`; диапазон отдыха «2–3 мин» — верхняя граница, 180;
- `time_sec: "max"` для «на максимум времени»; `reps: "max"` для «максимум повторов»;
- остаток записи, который не число (`на каждую букву`, `5 с на опускание`, техника) — в `notes`
  упражнения;
- не-упражнение (тест, замер, инструкция спортсмену) — блок `note` на его месте; напоминание тренеру
  (дата повтора) — в advice;
- разминка и заминка только на время: повторы перевести в секунды (≈3 с на повтор, округлить до 5 с;
  «5 × 3 с» → 15 с; стороны сохраняются, время на одну сторону) и одной заметкой advice перечислить
  переводы: «В разминке упражнения только на время: Мобилизация запястья 10 → 30 с, …»;
- текст «Описать свою» ссылается на название набора из библиотеки того же вида (разминка или
  заминка) — скопировать его упражнения по порядку, следом описанные; в advice «Взял за основу
  „…“». Набора с таким названием этого вида нет — ничего не копировать и сказать в advice;
- любое упражнение библиотеки годится в разминку.

Запрос (`server/aiPrompt.ts`): части с библиотекой упражнений и с наборами подписаны явно
(«id упражнений», «id разминок и заминок»), чтобы агент не путал их id. Порядок частей и точки кеша
не меняются.

### Сборка без отказа

`buildWorkout` (`web/src/features/builder/build.ts`):

1. Запрос, разбор; ошибки — один повтор с текстом ошибок, как сейчас.
2. Снова ошибки — чистая функция по путям ошибок правит ответ агента и запоминает пометки:
   - ошибка в нагрузке найденного упражнения (`reps`, `time_sec`, `weight_kg`, `sets`, `rest_sec`,
     `sides`) — поле заменяется значением по умолчанию (как при ручном добавлении в форме),
     упражнение получает пометку с тем, что написал агент, и текстом ошибки;
   - неизвестный `exercise_id`, сломанный блок — упражнение или блок убирается и попадает в список
     «Не разобрал»;
   - сломанная своя разминка или заминка — становится «без разминки», причина в «Не разобрал».
3. Повторный разбор исправленного ответа проходит; если нет — ошибка программы, показывается как
   сейчас.

`BuilderDraft` получает пометки (по id упражнения структуры) и список «Не разобрал». Открывается
обычная страница проверки черновика:

- помеченное упражнение стоит на своём месте с текстом «Проверьте нагрузку» (не только цветом) и
  тем, что написал агент;
- пометка снимается, когда тренер изменил нагрузку этого упражнения или убрал его;
- «Не разобрал» — список над формой рядом с заметками агента;
- «Сохранить» недоступна, пока есть пометки; рядом объяснение, сколько осталось.

Заметки агента теперь доходят до черновика: `notes` тренировки и упражнений разбираются, попадают в
структуру и в форму, тренер может их править.

### Страница «Формат импорта»

`format.ts` описывает v2: поля, блоки, примеры из раздела «Формат v2», частые ошибки. Одна строка:
«Файлы с version: 1 тоже читаются». Описание v1 со страницы уходит.

## Фикстура

Реальный запрос тренера (ноябрь 2026) — вход замера и тестов.

Разминка, «Описать свою»:

```
Хочу сделать новую разминку, которая дополнит упражнения из общей разминки следующими упражнениями:

Мобилизация запястья с движением 10
Открытая книга 5 на сторону
Поза 90/90 по 30 с
Удержание глубокого приседа 30 с
Подъём колена стоя с резинкой с удержанием 5 × 3 с на ногу
```

Основная часть:

```
1. Плечи: Лицевая тяга 12 раз, Y-T-W лёжа на животе 1 круг по 5 раз на каждую букву.

2. ПЕРЕПРОВЕРКА СТАРТА: максимум отжиманий на упорах (старт 8) → 3 мин отдых → вис максимум → 3 мин отдых -> максимум чистых подтягиваний → 3 мин отдых -> подъём коленей в висе. Рабочих подходов отжиманий сегодня нет.

3. Тест большого пальца: большой палец в кулак, кисть плавно наклонить в сторону мизинца. Записать: есть ли резкая боль у основания большого пальца и насколько сильная. Повтор — 08.12.

4. Подтягивания с резинкой: 35 кг 3 × 4 (после перепроверки). Оба колена в петле. Полная амплитуда: из виса на прямых руках до подбородка над перекладиной. Отдых 2–3 мин

5. Медленное опускание после запрыгивания на турник: 2 × 2 по 5 с.

2 круга следующих упражнений:
1. Сгибание руки с гантелью сидя с упором в бедро: локоть упирается в бедро и не двигается. 8 кг × 10–12. (упр. 12)
2. Мёртвая тяга с гантелей, 12–14 раз. Вес: ≈20 кг (две гантели) × 10–12
3. Лёжа животом на столе подъём ног до горизонтали, тазовые кости свисают, 12–14 раз.
```

Заминка, «Описать свою»:

```
Хочу сделать новую заминку, которая дополнит упражнения из общей разминки следующими упражнениями:

Растяжку верхней трапеции и мышцы, поднимающей лопатку, и Разгибание грудного отдела на МФР-ролле
```

Каждая запись из замера становится отдельным тестом:

| Запись из замера | v2 |
|---|---|
| отдых `3 мин`, `2-3 мин`, `2–3 мин` | агент пишет `rest_sec: 180`; тест схемы и разбора `rest_sec` |
| `time: max` | `time_sec: max` разбирается в `{0,0}`, kind time |
| `do: max` | `reps: max` |
| `do: 12-14` в круге | `reps: "12-14"` без `sets` |
| `do: 10-12 @ 8kg`, `do: 12-14 @ 20kg` | `reps: "10-12"`, `weight_kg: 8` |
| `do: 1x5 на каждую букву` | `sets: 1`, `reps: 5`, `notes` |
| `do: 2x2, 5 с на опускание` | `sets: 2`, `reps: 2`, `notes` |
| `do: тест` | блок `note` |
| `do` в v2 вообще | ошибка «в v2 — sets, reps и weight_kg» |
| повторы в разминке («Мобилизация запястья 10») | позиция `time_sec: 30`; упражнение с типом reps в наборе разбирается |
| неизвестный `exercise_id` | ошибка с ближайшими id; в сборке — в «Не разобрал» |
| id разминки вместо id упражнения | ошибка с подсказкой «это id разминки» |
| неверная нагрузка после повтора | черновик с пометкой, «Сохранить» недоступна |

Сырые ответы агента из замера пользователь сохраняет в
`web/src/features/builder/__fixtures__/` (JSON без секретов); тест прогоняет каждый через
`buildWorkout` с поддельным `send` и проверяет: черновик есть, пометок нет, «Не разобрал» пуст,
каждое упражнение запроса есть в черновике или в заметке о переводе.

## Замер

Делает пользователь вручную после третьего PR: до 4 сборок фикстуры, только Haiku 5.5, с
размышлением (adaptive, effort medium), как в ноябрьском замере. Сборка засчитывается, если
черновик открылся без пометок и без «Не разобрал» и ни одно упражнение не пропало молча. Цель —
3 из 4.

## Решения автора спека, не обсуждённые с пользователем

- В v2 нет `distance` (сейчас расстояние всё равно считается как 5 минут времени) и `lb`.
- Старый круг в YAML-редакторе переводится в «отдых после круга» при сохранении, с предупреждением.
- В блоке `sets` упражнение без `sets` — один подход (как сейчас в v1).
- Незнакомое поле в v2 — ошибка, а не предупреждение (в v1 — предупреждение, как сейчас).
- Набор для «дополнит общую разминку» ищется только среди наборов того же вида.
- Ответ на шаг-заметку пишется в поле на самом шаге и хранится в итоге тренировки, а не кнопкой
  комментария: комментарии держатся на slug упражнения библиотеки, которого у заметки нет.
- Тренировка из сборки без пометок, но с «Не разобрал», сохранять можно: пункты списка — сведения,
  а не блокировка.
