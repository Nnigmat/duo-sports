Продукт: мобильный веб-трекер тренировок с персонажем-чибиком (телефон в зале или
дома, может открываться внутри Telegram). Аккаунты создаёт админ, саморегистрации нет.
Роли: athlete, trainer, admin. Типы и режимы — в shared/types.ts, макеты — в design/.

Стек и ограничения:
- Без ORM: SQLite (better-sqlite3), чистый SQL, WAL и foreign_keys включены.
- Без CSS-фреймворков и тем: обычный CSS на переменных из tokens.css.
- Radix UI Primitives (@radix-ui/react-*, по одному под задачу) только для поведения
  и доступности (панели, переключатели). Простые элементы делаем сами; стили через
  className и data-state.
- Видео лежат в data/videos, в базе только путь. data/ в .gitignore.
- PWA: sw.js кеширует только оболочку (навигация, /assets/, иконки), не трогает /api/*
  и видео; только в продакшен-сборке; ничего не версионировать вручную.
- Новую зависимость добавлять только с объяснением, зачем она нужна.

Интерфейс:
- Русский, коротко, без «!» и эмодзи. Числа с единицей через пробел: «60 кг × 10»,
  «90 с», время мм:сс. Все числа — tabular-nums.
- Цвета и шрифты только через tokens.css.
- Кнопки не меньше 44 px, настоящие <button>/<a>/<input>+<label>. Состояние не
  только цветом. Учитывать prefers-reduced-motion и safe-area-inset снизу.

Работа:
- Маленькие шаги; после каждого npm run build без ошибок типов.
- Линтер Biome; исключения только через biome-ignore с причиной.
- Логику сценария тренировки держать чистыми функциями с тестами (vitest).

Git и CI:
- Коммиты по Conventional Commits 1.0.0; breaking change — `!` или `BREAKING CHANGE:`.
- Перед коммитом вызывать навык `/mattpocock-skills:pr`.
- В main напрямую не пушить: ветка → PR → зелёный check (как в ci.yml; перед PR
  прогнать lint, test, build, test:stories локально). Красные PR не мержить.
- Слияние в main деплоит на сервер (deploy.yml).
- Репозиторий публичный: никаких секретов, data/ и .env; секреты деплоя только в GitHub Secrets.

Данные на сервере:
- На проде приложение работает под pm2 (процесс duo-sport) из ~/duo-sport, а база и
  видео лежат вне репозитория: DATA_DIR=/var/duo-sport/data (app.db, app.db-wal,
  app.db-shm, videos/). Файл ~/duo-sport/data/app.db на сервере приложение не читает.
- Перед правкой базы вручную узнать реальный путь: у процесса node открыть
  /proc/<pid>/fd и /proc/<pid>/environ. Процесс npm базу не держит, lsof по pm2 pid
  её не покажет.
- Правки в базе только после копии: sqlite3 /var/duo-sport/data/app.db ".backup ~/app.db.bak".
  Скрипты правок писать идемпотентными (INSERT OR IGNORE по slug).
- Стартовый набор упражнений (DEFAULT_EXERCISES) кладёт ensureLibrary при первом
  запросе списка, и только пока таблица exercises пуста. Если вставить упражнения
  в пустую базу раньше, стартовый набор не появится.
- Редактор тренировки (YAML) и блоки warmup/cooldown с exercises берут упражнения из
  библиотеки и сами их не создают: сначала страница импорта с блоком exercises или
  вставка в таблицу, потом YAML тренировки без блока exercises.
- Из терминала YAML копировать только из файла (pbcopy < файл): длинные строки при
  копировании из вывода переносятся и ломают { … }.
